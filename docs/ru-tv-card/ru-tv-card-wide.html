Home Assistant — Android TV card, wide layout
Companion to TV Card, which holds the 390px phone options 1a/1b and the remote explorations 2a–2c. Same palette, same components, same simulated media_player — only the arrangement changes. This is the layout the card adopts on a wall tablet or in a panel-view dashboard.
3Wide layout — the card reflows itself when it is given room. No second card, no config option.
Driven by a CSS container query on the card's own width, not the viewport: @container (min-width: 640px). A card sitting in a narrow dashboard column stays on the 390px layout even on a wide screen — only the card's real width decides. 640px is the measured floor: 230px ring + 28px panel padding = 258 for the remote column, 260px transport row + 28 = 288 for the media column, plus 32px card padding and the 14px gap.
3aWide — the remote moves from below the media panel to beside it. Two columns: media takes the flexible one, the remote column is sized to the ring so it never squeezes. Panels stretch to equal height so they read as one row.

3dOpt-in on-screen keyboard (config keyboard: true, needs the remote entity) — a full-width third row under both panels. Printable keys type through the androidtv_remote IME text channel (keyboard_mode: text, default) or as raw key codes (keycode); backspace repeats while held, enter/backspace are key codes either way. Dismiss the TV's own on-screen keyboard (Back) before typing — Android TVs refuse concurrent virtual + on-screen keyboard input. Wide layout only — a phone column has no room for forty keys.
